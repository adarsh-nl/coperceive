# Add a dataset in 20 minutes

A dataset becomes a coperceive source by describing its layout in a YAML
manifest. No parser is written. The manifest names where the files are, which
reader opens them, what the numbers mean, and how the source axes map onto the
library's. The output is a schema 1 scene directory per scene
(`docs/spec/format.md`), the same thing the Griffin converter writes. The
design is [ADR 0009](../adr/0009-dataset-adapters.md).

This page walks through a synthetic KITTI-flavoured cooperative dataset. The
tree is generated by `tests/toy_dataset.py`, and `tests/test_adapter_toy.py`
runs every step below in CI. No real second dataset is ingested by this page.

## The tree

```text
raw/
  scene_0001/
    car_a/
      poses.csv                frame,stamp_s,x,y,z,qx,qy,qz,qw
      calib/cam_front.yaml     translation, rotation (deg), intrinsic, image
      calib/velodyne.yaml      translation, rotation (deg)
      labels/000000.txt        type h w l x y z yaw track   (bottom-centred boxes)
      velodyne/000000.bin      float32 x y z intensity
      image/cam_front/000000.png
    car_b/
      ...
  scene_0002/
    ...
```

The body frame of this source is `x` right, `y` forward, `z` up. The camera is
OpenCV style: `x` right, `y` down, `z` forward. Time is a float second count in
`poses.csv`.

## 1. Write down what is not in the files

Five things are never guessed. The manifest has to say them, and `adapters
check` refuses a manifest that leaves one out:

| Question | Key |
| --- | --- |
| How does the source time become microseconds? | `clock` with a `scale_note` |
| Which way do the body axes point? | `conventions.body_axes` (three letters from F/B/L/R/U/D) |
| Which way do the camera axes point? | `conventions.camera_axes` |
| Metres or centimetres, degrees or radians? | `conventions.length_unit`, `conventions.angle_unit` |
| How is a rotation encoded, and in which order? | `rotation` on each stream |

The library convention is `FLU` for a body (`+x` forward, `+y` left, `+z` up)
and `RDF` for a camera (`+x` right, `+y` down, `+z` forward). The builder
remaps the source onto that. Griffin is already `FLU` and `RDF`.

## 2. The manifest

```yaml
adapter: toy-coop
spec_version: 1

world_frame: map

clock:
  from: field
  field: stamp_s
  unit: s
  rounding: nearest
  scale_note: "stamp_s is a float second count in poses.csv, rounded to the nearest microsecond."

scenes:
  glob:
    path: "{scene}/"
    sample_source: boxes

agents:
  discover: {glob: "{scene}/{agent}/", type: vehicle}

conventions:
  length_unit: m
  angle_unit: deg
  body_axes: RFU
  camera_axes: RDF

streams:
  poses:
    reader: csv_rows
    path: "{agent_root}/poses.csv"
    sample_field: frame
    translation: [x, y, z]
    rotation:
      quaternion: {fields: [qx, qy, qz, qw], order: xyzw}

  sensors:
    reader: yaml_record
    path: "{agent_root}/calib/{sensor}.yaml"
    extrinsic:
      translation: [translation.0, translation.1, translation.2]
      rotation:
        euler: {fields: [rotation.roll, rotation.pitch, rotation.yaw], order: zyx, frame: intrinsic}
      direction: child_to_parent
    intrinsic: {fields: [intrinsic.fx, intrinsic.fy, intrinsic.cx, intrinsic.cy], optional: true}
    image_size: {fields: [image.width, image.height]}
    modality:
      - {has_intrinsic: true, modality: camera}
      - {default: lidar}

  boxes:
    reader: text_rows
    path: "{agent_root}/labels/{frame:06d}.txt"
    frame: body
    centre_origin: bottom
    variants:
      9: [category, height, width, length, cx, cy, cz, yaw, track_id]
    rotation:
      yaw_only: {field: yaw, axis: z}
    class_map: {Car: car, Pedestrian: pedestrian}
    class_map_unknown: error

  images:
    for_each: camera
    path: "{agent_root}/image/{sensor}/{frame:06d}.png"
    require_file: false

  lidar:
    reader: bin_f32
    sensor: velodyne
    path: "{agent_root}/velodyne/{frame:06d}.bin"
    stride: 4
    offsets: {x: 0, y: 1, z: 2, intensity: 3}

checks:
  required_per_sample: [poses, boxes, lidar]
```

Reading it top to bottom:

- `scenes.glob` finds one scene per directory. The sample list is whatever
  frames the `boxes` stream has files for. A dataset with an index file uses
  `scenes.index` instead (Griffin's `scene_infos.json` is the built-in example,
  `coperceive/adapters/builtin/griffin.yaml`).
- `agents.discover` makes one agent per sub-directory. A fixed list
  (`- {id: vehicle, type: vehicle, root: vehicle-side}`) is the other form.
- Path templates use a fixed set of placeholders: `{scene}`, `{agent}`,
  `{agent_root}`, `{sensor}`, `{frame}` (an integer, `{frame:06d}` pads it) and
  `{sample}` (a string key). There is no regex, `..` is refused, and every
  resolved path has to stay under `--raw-root`.
- `poses` is one CSV table per agent, keyed by `sample_field`. One record per
  sample (`json_record`, `yaml_record`) is the other shape. A quaternion names
  its field order; Euler angles are always `[about_x, about_y, about_z]` and
  `order` says how they compose.
- `sensors` reads one calibration file per sensor. The extrinsic is a 4×4
  matrix (`matrix: {field: extrinsic, shape: 4x4}`) or a translation plus a
  rotation. `direction` says which way the matrix goes. The first matching
  `modality` rule wins and the last rule has to be `default`.
- `boxes` are whitespace rows. `variants` maps a field count to column names,
  so a file that mixes 12- and 9-field lines is one stream. The columns are
  named, so `h w l` order is written as such. `centre_origin: bottom` lifts the
  centre by half the height. `yaw_only` is a single angle about one axis.
- `lidar` is headerless float32 with a stride. `ply` and `pcd` take a
  `fields` map instead. A source with no intensity says
  `intensity: {fill: 0.0, reason: "..."}`; it is never filled silently.

## 3. Check it

```bash
coperceive adapters check toy.yaml --raw-root raw
```

`check` validates the manifest, discovers the scenes, reads the first and last
sample of every stream for every scene, builds each scene in memory, and
prints counts. It writes nothing. An unknown key is reported with its path
(`streams.boxes: unknown key 'colour'`). A field that is missing from a file is
reported with the file.

```text
adapter toy-coop
scenes 2
scene_0001	agents=2 boxes=8 images=4 lidar=4 poses=4 sensors=4
scene_0002	agents=2 boxes=8 images=4 lidar=4 poses=4 sensors=4
label_fields 9:16
```

## 4. Ingest it

```bash
coperceive adapters ingest toy.yaml --raw-root raw --out scenes
coperceive validate scenes
coperceive serve --host 127.0.0.1 --root scenes
```

`ingest` is the same driver Griffin uses: scenes in parallel (up to 8), a
`.partial/` directory per scene while it is written, and a `COMPLETE.json`
marker that lets a second run skip finished scenes. The marker also records
the adapter name, the manifest's SHA-256 and the coperceive version.

A manifest with parameters (Griffin's `subset`) takes them on the command
line: `--param subset=25m`. `--scenes a,b` limits a run.

## 5. Share it

Three ways, in order of effort:

1. Keep the YAML next to your data and pass its path.
2. Ship it in a package and register it: in `pyproject.toml`,
   `[project.entry-points."coperceive.adapters"] mydata = "mypkg:MANIFEST"`,
   where `MANIFEST` is a `pathlib.Path` to the YAML, an adapter object, or a
   zero-argument function returning one. `coperceive adapters list` then shows
   it.
3. Open a pull request adding it to `coperceive/adapters/builtin/`.

## When a manifest is not enough

A file format the built-in readers do not open gets a reader plugin, not a
manifest key. Register a callable under `coperceive.readers` with a `kind`
attribute: `record` (`(path) -> dict`), `table` (`(path) -> list[dict]`) or
`lidar` (`(path, *, fields, intensity_fill=None) -> (count, bytes)`, bytes
being little-endian float32 `x, y, z, intensity`). The manifest names it by its
entry-point name in `reader:`. A dataset whose structure the vocabulary cannot
express implements the `Adapter` protocol in Python
(`coperceive.adapters.ingest.Adapter`) and registers that instead.

Readers and adapters run inside the `coperceive` process, like any installed
package. Model plugins on the roadmap are the ones that run in a subprocess.

## What was checked

The toy manifest, the Griffin manifest and every reader run in CI on synthetic
trees. The Griffin adapter is compared against the hand-written converter
(`tests/test_adapters_griffin.py`): byte-identical `manifest.json` and
`points.bin`, equal Parquet tables, equal scenes. The same comparison on the
real Griffin-25m release is the slow test in that file and needs
`COPERCEIVE_GRIFFIN_RAW`. No OPV2V, V2XSet, DAIR-V2X or nuScenes tree has been
opened with these readers.
