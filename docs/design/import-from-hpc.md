# Import prepared scenes from the HPC

Proposed on 2026-11-22 for v0.1.3 (feature B), for PM review and Adarsh's approval. No
product code until it is approved. Code is cited from `release/v0.1.3` at `17b4ea0`. Anything the code
does not settle is marked **unverified**.

**Goal:** copy prepared scenes from a cluster cache split into the laptop library, so they
open offline.

**Not in scope:**
- raw dataset files;
- uploading to the cluster;
- any HPC-only dataset, until Adarsh decides.

## 1. Licences, per dataset

| Dataset | What the repo records | Source in the repo | Proposed import |
|---|---|---|---|
| Coperceive demo (synthetic) | Apache-2.0, generated by code in this repository | `coperceive/bundle/sensor.py` (`DEMO_LICENCE`, generator marker) | **allow**. Today no cluster cache can hold a demo scene: prepare accepts only the built-in adapters (`cluster_datasets.py:56`, no `generic`). The row applies only if that changes. |
| Griffin | MIT: the toolkit LICENSE and the HF card `license: mit`, both fetched 2026-10-24. `requires_terms: true`. | `coperceive/catalog/datasets.yaml` | **warn**: the user's own terms acknowledgement first |
| OPV2V | `status: unknown`. "Research use on the HPC only; no frames, crops, screenshots or derived scene files in a public repository" | `adapters/builtin/opv2v.yaml` | **block** |
| V2XSet | `status: unknown`, same wording | `adapters/builtin/v2xset.yaml` | **block** |
| V2V4Real | `status: unknown`. The repository LICENSE covers the code, not the data. HPC only. | `adapters/builtin/v2v4real.yaml` | **block** |
| DAIR-V2X-C | `status: unknown`. "Research use on the HPC only." | `adapters/dair_v2x_c.py` (`_Licence`) | **block** |

- **DECISION (Adarsh):** Griffin as **warn** or as **allow**.
  - Its terms are per user: `requires_terms: true`, and the bundle allow list refuses its
    frames for that reason (`bundle/sensor.py`).
  - Importing to the same user's laptop is not passing frames on. But the person
    importing may not be the one who accepted the terms for the cluster copy.
- **DECISION (Adarsh):** every HPC-only dataset stays **block** until you decide
  otherwise, one dataset at a time.
- **So the only importable path today is Griffin** (warn, or allow if you choose it).
- **Already true today, outside this feature:**
  - Viewing any cluster dataset keeps up to 2 GB of streamed bytes in a local cache:
    `remote_view/scenes.py`, `DEFAULT_CACHE_BYTES`, and Settings → Clear cache.
  - That cache holds HPC-only data too. It is bounded and is not a library scene.
  - **DECISION (Adarsh):** whether that stays acceptable.

## 2. Policy: driven by the manifest

- **A new field, `licence.import: allow | warn | block`:**
  - It goes in each manifest's `licence` block, parsed in `adapters/spec.py` › `_licence`,
    and on DAIR's `_Licence`.
  - A missing field means **block**.
  - `griffin.yaml` has no `licence` block today. It gets one: `status: known`,
    `spdx: MIT`, with the catalog's sources.
- **Which policy applies:** the laptop's own copy of the manifest decides, never the
  server.
  - The adapter comes from the scene's `COMPLETE.json`. It must match the cache's
    `dataset.json` adapter.
  - Only the generator marker makes a scene the demo, the same rule the bundle uses. A
    folder name or a typed id never does.
- **Warn:**
  - Before anything is copied, the app shows the manifest's `notice` and links.
  - For Griffin it also requires the terms acknowledgement (`griffin/licence.py` ›
    `acknowledgement_present`).
- **Block:**
  - The Import action is visible but disabled, with the manifest's notice as the reason.
  - The CLI refuses with the same text.
  - Nothing is listed, sized or read.

## 3. Transfer, verification and placement

- **Transfer:**
  - The transfer uses the existing read-only streamer, `coperceive dataset stream`.
  - Every path it serves is confined, by realpath, to the cache split and the raw root.
    It refuses `..`, absolute paths and symlink escapes (E2E step CD-17).
  - It submits no job and writes nothing on the cluster.
  - The streamer has `read`, `stat`, `ready_scenes`, `ping`, `cancel` and `stats`
    (`remote_view/stream.py`). Import adds one read-only op, `files`, under a new
    capability:
    - it returns a scene's `FILES.json`;
    - for previews and originals, it adds the image list from `images.parquet`.
- **Verification:**
  - **The prepare job writes `FILES.json`**, with each file's relative path, size and
    sha256. Hashing then happens in the job, not on the login node.
  - The laptop hashes each file as it writes it, and compares the hash with `FILES.json`.
  - Any size or hash mismatch fails that scene; nothing is placed.
  - **Originals are raw files, not cache files, so `FILES.json` does not list them.**
    Proposed: they are hashed by the same job, on request, into `ORIGINALS.json`, and
    verified the same way. Without it, Originals is not offered. Hashing originals in
    every prepare would read every camera file once more.
  - **DECISION (Adarsh):** scenes prepared before `FILES.json` existed. Either import
    them after a small hashing CPU job you submit (recommended), or Re-prepare them. Hashing
    them over the login node is not proposed.
- **Atomic placement:**
  - Files land in `<library>/<dataset>/<scene>.partial/`.
  - `COMPLETE.json` and `IMPORT.json` are written last, then the directory is renamed to
    `<scene>/`. This is the same pattern as `scene/pack.py` and `adapters/ingest.py`.
  - A resumed import skips a file whose size and sha256 already match.
  - A scene already in the library with the same provenance is skipped. A different one
    is refused, unless the user chooses Replace.
- **Disk check:**
  - It runs before the first byte. The required space is the sum of the sizes in
    `FILES.json`, plus the chosen images.
  - It uses the existing rule: refuse when free minus required is under 10 % of free
    (`catalog/runner.py`).
  - It runs again before each scene (`library.rs` › `statvfs`).
- **Provenance: `IMPORT.json`** (the name `scene/pack.py` already uses) records:
  - the server profile id, never a host or user name;
  - `cache_relative_path`, never a site path;
  - the adapter and its `manifest_sha256` from `COMPLETE.json`;
  - the coperceive version on both sides;
  - the licence status and import policy at import time;
  - the import time;
  - the sha256 of `FILES.json`.
- **Path-traversal guards, on the laptop side too:**
  - Scene ids go through `safe_scene_id`.
  - Every listed path must be relative POSIX, with no `..`, no NUL, and not absolute.
    Nothing under `raw/` is copied except listed originals.
  - The resolved target must stay inside `.partial/`.
  - No symlink is ever created locally. Every cache scene's `raw` → raw-root link is
    never followed (`docs/datasets/cluster-datasets.md`, camera images).

## 4. Camera images

| Choice | What is copied | Size |
|---|---|---|
| **Previews** (proposed default) | The cache's 640 px JPEGs, `previews/<path>.jpg` | about 40 KB per camera frame (`cluster-datasets.md`) |
| Originals | Only the `raw/<path>` files that `images.parquet` lists, through the streamer's media root. Their paths are rewritten to the local copy. | dataset-specific. Griffin's RGB cameras plus its metadata and LiDAR archives total 162,515,011,954 bytes for the 25 m subset (catalog dry-run, 2026-10-24) |
| None | LiDAR, boxes and poses only | — |

- A split prepared without previews offers Originals or None, never a silent switch.
- **DECISION (Adarsh):** the default (Previews proposed), and whether Originals needs a
  size confirmation above a threshold.

## 5. Tests and acceptance, after approval

- **Policy:**
  - every built-in adapter resolves to its row in the table;
  - a manifest without `import` blocks;
  - a typed "demo" id without the marker blocks.
- **Guards:**
  - `..`, absolute, NUL and `raw/` paths are refused;
  - a symlink in `FILES.json` is refused;
  - a target outside `.partial` is refused.
- **Transfer:**
  - a hash or size mismatch places nothing;
  - an interrupted import resumes and places the scene once;
  - a full disk refuses before the first byte.
- **Fake-SSH E2E:**
  - import a synthetic Griffin release (`tests/griffin_release.py`) after the terms
    acknowledgement, and open it offline;
  - an `opv2v` split shows Import disabled and makes no `files` request;
  - nothing is written on the fake cluster.
- **Fixtures:** all synthetic. No dataset frames in tests or docs.
