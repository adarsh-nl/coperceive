# Coperceive v0.1.1 Release Notes

Coperceive **v0.1.1** expands the desktop application from macOS Apple Silicon
to **Windows, Linux, and Intel Mac**, adds an **offline first-run demo scene**,
introduces **viewer visual styles**, adds dataset adapters for **V2V4Real**,
**DAIR-V2X-C**, and **generic multi-view folders**, and expands evaluation,
reproducibility, and paper export tooling.

---

## What's New

### Desktop Installers & Auto-Updates Across 4 Targets
- **Native installers for three operating systems**:
  - **macOS (Apple Silicon `arm64` & Intel `x86_64`)**: Disk images
    (`Coperceive_0.1.1_aarch64.dmg` and `Coperceive_0.1.1_x64.dmg`).
  - **Windows (`x86_64`)**: Per-user NSIS installer
    (`Coperceive_0.1.1_x64-setup.exe`) with silent `/S` install and uninstall
    support.
  - **Linux (`x86_64`)**: Portable `Coperceive_0.1.1_amd64.AppImage` and
    Debian/Ubuntu package (`Coperceive_0.1.1_amd64.deb`).
- **Bundled standalone Python runtime**: Every installer ships a self-contained
  CPython 3.13.1 runtime with locked, hash-verified dependencies—no local Python
  installation or Terminal setup is required to run the desktop app.
- **Four-target updater manifest (`latest.json`)**: In-app updates cover
  `darwin-aarch64`, `darwin-x86_64`, `windows-x86_64`, and `linux-x86_64`
  (AppImage), with all updater archives verified against the embedded minisign
  public key. Linux `.deb` installations suppress the in-app update banner and
  direct users to `apt` or GitHub Releases on manual update checks.
- **OS-aware download panel on the public site**: The landing page offers the
  matching installer for the visitor's OS and CPU architecture (or both macOS
  disk images when the browser does not report the chip) and automatically
  switches to newly published GitHub releases without waiting for a site
  rebuild.

### First-Run Demo Mode
- **Welcome card on an empty Library**: When no local datasets or remote servers
  are configured yet, the Library shows a welcome card after choosing the
  library folder, with two actions:
  - **Open the demo** (primary): Generates a deterministic 3-agent cooperative
    four-way junction scene (`demo-junction`: two vehicles `cav-a` and `cav-b`
    with LiDAR and a front pinhole camera, plus one roadside unit `rsu` with
    LiDAR; no drone and no HD map; 100 frames at 10 Hz with 10 moving actors—4
    cars, 1 cyclist, and 5 pedestrians—and one synthetic prediction run `demo`)
    offline using the bundled Python runtime (`coperceive demo create`). Stored
    inside the application data directory (`<state_dir>/demo/`) and cached for
    instant subsequent opens. On disk, the ingested scene directory
    `scenes/demo-junction/` is 1.7 MiB (`1,818,047` bytes) as shown in the
    Library table, and the full `<state_dir>/demo/` tree (including `raw/` and
    `predictions/`) is 7.8 MiB (`8,218,139` bytes; the welcome card button shows
    the hard-coded UI string `~8.2 MB`).
  - **Try a real sample (Griffin, MIT licence)**: Opens **Get Data** with the
    Griffin `dev` preset (`Dev tier`) pre-selected. The welcome card button
    displays `Dev sample · 143 MB download from Hugging Face` (`LibraryScreen.tsx:242`),
    and **Get Data** runs a live Hugging Face dry run showing `228.6 MB`
    (`239,749,191` bytes) for `Dev tier` before downloading.

### Viewer Styles & "Seen By" Box Colouring
- **Viewer styles (`Settings → Viewer → Style`)**: Choose between **Classic**
  (default), **Studio**, **Instrument**, and **Cinema**, each with a live
  preview in Settings and persisted immediately in `state.json`. Cinema's subtle
  camera drift respects `prefers-reduced-motion`.
- **Colour boxes by observer ("Seen by")**: Colour 3D bounding boxes by who
  recorded them (**both**, **ego only**, **other agent**) on datasets that store
  per-agent annotations with a shared track ID (**OPV2V** and **Griffin**).
  Automatically hidden for datasets without shared cross-agent track IDs
  (V2XSet, V2V4Real, DAIR-V2X-C, generic scenes, and the demo).

### Windows & Linux Platform Integration
- Native window decorations on Windows and Linux, application menu with `Ctrl`
  accelerators, and platform-native file-manager reveal labels (**"Show in
  Explorer"** on Windows, **"Show in folder"** on Linux, **"Show in Finder"** on
  macOS).
- Windows OpenSSH support (`%USERPROFILE%\.ssh\config` with `ControlMaster=no`),
  download job pause and resume on Windows, strict ACL / file-mode checks on
  credentials and state files, and cross-platform diagnostics `.zip` export.

### Datasets & CARLA HD Road Maps
- **V2V4Real adapter & detection**: Supports the OpenCOOD V2V4Real layout at
  10 Hz (`0.1 s` per frame) with box angles `[roll, yaw, pitch]` in degrees and
  optional camera records so the LiDAR-only test release validates and plays
  cleanly.
- **DAIR-V2X-C adapter & detection**: Built-in adapter and automated directory
  detection for cooperative vehicle–infrastructure scenes.
- **Generic multi-view scene format**: Ingest and validate custom multi-agent or
  multi-camera folders via `coperceive/adapters/generic.py` with two runnable
  examples.
- **One-click CARLA town road maps**: Download, verify, and align CARLA
  OpenDRIVE HD maps from the viewer or Settings, distinguishing towns verified
  against the official CARLA 0.9.15 package (`Town03`, `Town06`, `Town07`,
  `Town10HD`) from towns matching public mirrors (`Town01`, `Town02`, `Town04`,
  `Town05`).

### Evaluation, Reproducibility & Sharing
- **Multi-run breakdowns, failure ranking & robustness perturbations**:
  Compare 2 to 4 runs with distance/occlusion breakdowns (`coperceive eval
  compare`), rank worst frames and tag failure modes (`coperceive eval
  failures`), and run seeded sensor/pose perturbations (`coperceive model run
  --perturb`).
- **Portable reproducibility cards**: Export secret-scrubbed repro cards
  (`coperceive repro export` and from Run History) capturing manifest hashes,
  checkpoints, hardware, and runtime environment while scrubbing usernames,
  hostnames, and home paths.
- **Overleaf paper bundle export**: Export a scored run to a ready-to-compile
  Overleaf `.zip` (`coperceive export paper` and from the desktop UI) with a
  LaTeX metrics table, BEV/overlay figures, BibTeX citations, and README.
- **Lab server profile sharing**: Export and import `.coperceive-server.json`
  profiles without secrets, with trust warnings and stricter SSH identity path
  validation.

## What Changed

- **Python 3.11+ required (Python 3.10 dropped)**: When installing `coperceive`
  from source, the minimum supported Python version is now **3.11** (3.11 to
  3.13) because Pillow 13 dropped Python 3.10 support. *(Desktop app users are
  unaffected: the app bundles its own Python 3.13.1 runtime, and the released
  v0.1.0 desktop app already bundled Pillow 13.0.0.)*
- **Security hardening**: Upgraded Pillow to `13.0.0` in `uv.lock` and `tokio`
  to `1.54.1`, and restricted Pillow image decoders strictly to **PNG and JPEG**
  to reduce parser attack surface.

## Known Limits

1. **Intel Mac (`x86_64`) verified under Rosetta 2 only**: The Intel macOS disk
   image (`Coperceive_0.1.1_x64.dmg`) is cross-compiled on Apple Silicon CI
   runners and smoke-tested under Rosetta 2 emulation (`arch -x86_64`). It has
   not yet been tested on physical bare-metal Intel Mac hardware.
2. **Windows installer is unsigned (SmartScreen warning)**:
   `Coperceive_0.1.1_x64-setup.exe` is not Authenticode-signed. On first launch,
   Windows SmartScreen will display *"Windows protected your PC"* — click **More
   info** → **Run anyway** to run the installer.
3. **macOS builds are not signed with a Developer ID and not notarized**: Both
   macOS disk images are not signed with an Apple Developer ID certificate and
   are not notarized with Apple. On first open, macOS Gatekeeper requires
   **right-click → Open** (or allowing the app under **System Settings → Privacy
   & Security**) before launching normally.
4. **V2V4Real coordinate convention is provisional**: The V2V4Real adapter
   applies the provisional OPV2V left-to-right `y`-reflection (`world_frame:
   v2v4real-world`) and displays an unverified coordinate-convention warning
   until a real extracted scenario is visually checked for road-side handedness
   on the cluster. In addition, V2V4Real's per-CAV `vehicles` dictionary keys
   are not shared cross-agent track IDs (`ass_id` is not read), so "Seen by" box
   colouring is hidden for V2V4Real.
5. **Demo predictions are synthetic**: The single prediction run (`demo`, model
   `"synthetic demo"`, source `"noisy"`) bundled with the offline first-run demo
   scene (`demo-junction`) consists of deterministically generated noisy boxes
   with simulated misses—not outputs of a trained perception model—and is
   labelled **synthetic predictions** throughout the UI.
