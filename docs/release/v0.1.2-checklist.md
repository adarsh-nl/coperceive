test) and what only a human can verify before, during, or after tagging. A
release needs every row green or explicitly waived by Adarsh. Agents never tag,
merge, edit, or publish a release; Adarsh does.

That URL only serves `v0.1.2`'s `latest.json` once the `v0.1.2` GitHub Release is published and marked **Latest**. |

### Exact steps for testing the `v0.1.1` → `v0.1.2` update

#### Part A — Before tagging `v0.1.2` (prepare the `v0.1.1` baseline)

- [ ] 1. Install the released `v0.1.1` build (`Coperceive_0.1.1_aarch64.dmg` from
  `https://github.com/adarsh-nl/coperceive/releases/tag/v0.1.1`) into
  `/Applications/Coperceive.app` (right-click → Open the first time).
- [ ] 2. Launch `/Applications/Coperceive.app`.
  - Open **Coperceive → About Coperceive** (or **Help → About**) and confirm it
    shows **`v0.1.1`**.
  - Click **Help → Check for Updates…** while `v0.1.1` is still the Latest
    GitHub release.
  - **Expected:** Toast says **`You're up to date (0.1.1).`** and no sidebar
    update card is shown.
- [ ] 3. Quit `/Applications/Coperceive.app` and leave it installed in
  `/Applications` ready for Part B.

#### Part B — Immediately after tagging and publishing `v0.1.2` (requires the published release)

- [ ] 4. Once the `Release` workflow on tag `v0.1.2` finishes (`C5`), confirm in
  a terminal that GitHub's `latest` endpoint is live and serving `0.1.2`:
  ```bash
  curl -fsSL https://github.com/adarsh-nl/coperceive/releases/latest/download/latest.json | jq -r '.version, (.platforms | keys[])'
  ```
  **Expected:** Prints `0.1.2` followed by `darwin-aarch64`, `darwin-x86_64`,
  `linux-x86_64`, and `windows-x86_64`.
- [ ] 5. Launch the installed `v0.1.1` app (`/Applications/Coperceive.app`). If
  it was already running, click **Help → Check for Updates…**.
  **Expected:** The sidebar card above **Settings** appears:
  - Title: **`New update available`**
  - Version line: **`coperceive 0.1.2 is ready`**
  - Buttons: **`What's new`**, **`Install`**, and **`✕`** (`Later`).
- [ ] 6. Click **`What's new`** and confirm the popover opens for
  `coperceive 0.1.2`. Click **`✕`** (`Later`) and confirm the card hides for the
  session; then click **Help → Check for Updates…** and confirm the card comes
  back.
- [ ] 7. Click **`Install`**.
  **Expected:**
  - The card changes to **`Downloading update…`**.
  - `tauri-plugin-updater` downloads `Coperceive_aarch64.app.tar.gz` from the
    `v0.1.2` release, verifies `Coperceive_aarch64.app.tar.gz.sig` against
    public key `9AB294B56FC3C444`, replaces `/Applications/Coperceive.app` in
    place, and relaunches the app automatically.
- [ ] 8. After the app relaunches:
  - Open **About Coperceive** and **Help → Copy Diagnostics**: both must report
    **`0.1.2`**.
  - Click **Help → Check for Updates…**: toast must say **`You're up to date
    (0.1.2).`** and the sidebar update card must not appear.

### What to do if the update fails after tagging

1. **Stop offering `v0.1.2` immediately (rollback `Latest` to `v0.1.1`):**
   - On GitHub, open **Releases → `v0.1.1` → Edit**, tick **Set as the latest
     release**, and click **Update release** (or run
     `gh release edit v0.1.1 --latest`).
   - Because the app polls `/releases/latest/download/latest.json`, setting
     `v0.1.1` back as Latest immediately serves `v0.1.1`'s `latest.json`
     (`"version": "0.1.1"`). **Never delete the `v0.1.1` release.**
2. **If the failure was only in release assets or `latest.json`:**
   - Check the error shown in the sidebar card and inspect `latest.json` on the
     `v0.1.2` release (every platform entry must carry a valid minisign signature
     matching `plugins.updater.pubkey`).
3. **If the failure is a bug in the `v0.1.2` binary itself:**
   - Any installation that already updated to `v0.1.2` will stay on `v0.1.2`
     because the Tauri updater never downgrades (`0.1.2` → `0.1.1`). Fix the
     issue on `main`, verify with `release.yml`, and tag and publish **`v0.1.3`**.

## C3. V2V4Real mirror / coordinate-convention check

### What CI already proves

- `tests/test_adapters_v2v4real.py` verifies `coperceive/adapters/builtin/v2v4real.yaml`
  on synthetic OpenCOOD V2V4Real-layout fixtures:
  - 10 Hz frame clock (`scale_us: 100000`, 0.1 s step per the CVPR 2023 paper);
  - optional camera sensor records (`records: {prefix: camera, optional: true}`)
    so the LiDAR-only release validates and plays with no camera sensors;
  - box angles `[roll, yaw, pitch]` in degrees;
  - provisional `source_handedness: left`, `reflect_axis: y` (`world_frame:
    v2v4real-world`) and the unverified coordinate-convention warning;
  - viewer hides "seen by" colouring for V2V4Real (`web/src/viewerStyle.test.ts`).
- `docs/geometry/conventions.md` (`V4R-1`, currently citing draft PR #166 /
  PR #201) records the probe's traffic-side evidence: axes and handedness are
  **unverified**, and the adapter currently mirrors poses, boxes, and points on
  a CARLA assumption (`reflect_axis: y`).
- **Unverified cluster-side item from `CHANGELOG.md`:** the earlier V2V4Real
  `"detect 9 / index 0"` report could not be reproduced end to end on fixtures (a
  V2V4Real-shaped fixture detects 9 scenes and indexes 9); the cluster-side
  reason real scenes were unreadable remains **unverified**, and the Servers
  browser now diagnoses detect/index disagreements when they occur.

### What only a human can check on the cluster

- [ ] On the cluster where `/data/opencood/v2v4real/test/` is extracted (9
  scenarios, LiDAR-only, `docs/datasets/v2v4real.md`):
  1. Index and prepare one scenario (for example
     `testoutput_CAV_data_2022-03-15-09-54-40_0`) and open it in the viewer.
  2. Check whether the vehicles drive on the **right-hand side of the road**
     (Columbus, Ohio real-world driving) and turns/intersections match natural
     right-hand traffic, or whether the scene is left–right mirrored.
  3. **Decision rule (`this human check decides reflect_axis`):**
     - If the scene is mirrored, remove `reflect_axis: y` in
       `coperceive/adapters/builtin/v2v4real.yaml` (and update `V4R-1` in
       `docs/geometry/conventions.md`).
     - If it is not mirrored (right-hand traffic matches Columbus, Ohio), keep
       `reflect_axis: y` and mark `V4R-1` verified / remove the provisional
       warning.
