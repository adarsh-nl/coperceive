# Coperceive v0.1.2 Release Notes *(Draft)*

> **Draft status:** Built from `CHANGELOG.md` `[Unreleased]` ahead of tagging
> `v0.1.2`. Two breaking/notice sections at the top (**Numbers change** and
> **Geometry fixes, re-prepare your scenes**) await upstream PRs before tagging
> and are explicitly marked pending below.

---

## Numbers change *(pending PR #165)*

- *(pending PR #165)* The default AP protocol changed (per-frame ranking, ground
  truth from every connected agent within 70 m), so AP values differ from
  v0.1.1 for the same predictions. Use `--protocol legacy` to reproduce
  v0.1.1's numbers.
- *(pending PR #165)* Class and model means are now summed exactly, so they can
  differ from v0.1.1 in the last digit.

## Geometry fixes, re-prepare your scenes *(pending the adapter-conventions PR)*

scene geometry matches the corrected conventions.

## Added

- **Read-only Result Bundle Viewer (`Open bundle…` and `coperceive serve`)**:
  Open exported `.cpbundle` archives directly in the viewer (read-only) to
  inspect frames, ground truth, predictions, and scores. A banner clearly
  states whether sensor data is included directly (allowed only for Coperceive's
  synthetic demo scenes when exported with sensor data and within the 50 MiB
  size cap, checked before writing and before extraction), loaded in place from
  your own local library copy of the same scene without copying, or omitted with
  the reason—third-party datasets, including Griffin, never travel inside
  bundles. `coperceive serve --root <bundle>/scenes --predictions
  <bundle>/predictions --bundle-info <bundle>/open.json` serves the same view
  with token, CSRF, and loopback `Host` checks enabled.
- **Concurrent, cancellable cluster-dataset streaming (protocol 2)**:
  Remote dataset streaming now answers requests concurrently on a bounded worker
  pool for protocol-2 clients (while protocol-1 clients retain serialized
  in-order replies), so large point-cloud sweeps no longer stall small manifest
  or stat replies. Cancelling a frame read on disconnect or seek skips queued
  work and drops in-flight replies; bounded timing statistics (`queue_ms`,
  `read_ms`, `bytes`) are available at `GET /api/stream-stats`, alongside
  `scripts/bench/stream_bench.py` for streaming measurements.
- **Configurable time-based viewer streaming buffer (`Settings → Viewer`)**:
  Replaces the fixed four-frame prefetch horizon with a priority scheduler
  (current frame, boxes, then prefetched sweeps), a configurable lookahead
  buffer (`1 s`, `3 s` default, or `5 s`), and a configurable client memory cap
  (`256 MB`, `512 MB` default, or `1024 MB`) that evicts frames behind the
  playhead first. The timeline shows a buffer bar, playback pauses cleanly with
  `"Buffering…"` until at least `1 s` is buffered, and an optional stats line
  reports buffer-ahead duration, throughput (`MB/s`), and frame-load `p50`/`p95`
  latencies.

## Changed

- **`coperceive serve` authentication, `Host`, `--token-file`, and SQLite hardening**:
  - Bearer-token and `X-Coperceive-Request` checks now apply to all `/api` routes
    even when `--root-path` is configured.
  - Without a token, `coperceive serve` now accepts only `127.0.0.1`,
    `localhost`, or `[::1]` on its own listening port and returns HTTP `400`
    for any other `Host` (including SSH tunnels mapped to a different local
    port; keep the same port or configure `COPERCEIVE_TOKEN` / `--token-file`).
  - `--token-file` must be a non-empty regular file owned by you, not a
    symbolic link, with mode `0600` or `0400` (empty token files now fail).
  - `jobs.sqlite` (and `-journal`/`-wal`/`-shm`) must be a regular non-linked
    file created with `O_EXCL|O_NOFOLLOW` inside the opened folder; symlinks,
    hard links (e.g. from `rsync --link-dest`), FIFOs, and directories are
    refused with `400`.
  - Rerun export filenames use the scene ID only when it contains plain
    characters (`A–Z`, `a–z`, `0–9`, `_`, `-`); otherwise they fall back to the
    folder name or `scene`.
- **Safe OpenCOOD checkpoint config loading & PyTorch version gate**:
  - OpenCOOD checkpoint `config.yaml` files are now parsed by default with a
    restricted safe loader (handling OpenCOOD floats, `!!python/tuple`, numpy
    YAML tags as data, and `load_<name>_params` lookups) instead of running
    arbitrary code; loading unsupported YAML tags/expressions or loading weights
    on PyTorch older than `2.6.0`, `2.6.0` pre-releases, or unreadable PyTorch
    versions requires upgrading PyTorch or explicitly passing
    `--option trust_checkpoint_pickle=true`.
  - PEP 440 PyTorch `2.6.0` post-releases (such as `2.6.0.post1` or
    `2.6.0.post100+cpu`) are accepted without needing `trust_checkpoint_pickle`.
    `plugin.log` records `config_loader=safe` or `config_loader=opencood load_yaml (trusted)`.
- **Stricter server-profile, SSH, and saved-plan path rules**:
  - Results folders containing spaces, `#`, `$`, backticks, quotes, backslashes,
    control characters, or a leading `~` are refused on save, lab-profile import,
    and run/prepare script generation (existing saved profiles with spaces or
    `~` in the results folder must be updated to an absolute path without
    spaces/`#`/quotes before the next run; code folders with spaces or `~/`
    continue to work when free of shell metacharacters).
  - Dataset-preparation scripts reject job names, partitions, and time limits
    containing spaces, `#`, or quotes; SSH invocations always pass `--` before
    the destination and reject aliases, hostnames, or usernames starting with `-`.
- **CLI Slurm, manifest, remote session, and map-archive checks**:
  - `coperceive model run --slurm` and `robustness sweep --slurm` restrict
    scratch templates to `$USER` / `$SLURM_JOB_ID` (and `${...}` equivalents)
    without `..` or `~`, validate run IDs, manifest names/keys/modules/artifact
    names/Slurm constraints/checkpoint paths/Python paths, and validate
    `--slurm-logs` folders against whitespace or control characters.
  - `coperceive remote start --uuid` requires plain 1–128 character IDs
    (`[A-Za-z0-9._-]+`), and control characters in roots/paths are refused.
  - `coperceive maps fetch` reads `.xodr` archive members in 1 MiB chunks,
    refuses members over 20 MiB (keeping any prior valid file), refuses GNU/pax
    extended headers over 64 KiB or more than 8 extensions, refuses GNU sparse
    members, and streams headers without holding every header in memory.
  - `scripts/check_bundle_assets.py` extracts `.deb` archives with Python's
    `tarfile` `"data"` filter.
- **Strict Result Bundle export & open link/file checks (`FOLD-03`)**:
  - Bundle export and preview refuse symlinks, hard links, FIFOs, non-regular
    files, and missing recorded camera files (exception: prepared cluster `raw`
    camera links are omitted—never followed—when sensor data is excluded and
    listed under `omitted_links`, or refused if sensor data is included).
  - Secret-like keys (`password`, `secret`, `token`, `api_key`, `access_key`,
    `private_key`, `authorization`, and suffixes such as `hf_token` or
    `X-Api-Key`) are scrubbed to `"<redacted>"` across staged JSON files, and
    served bundle jobs directories are cleaned up at shutdown and on later runs.
  - Opening a bundle rejects reserved member collisions (`open.json`,
    `BUNDLE.JSON`), enforces the 50 MiB sensor cap across all non-table files
    under `scenes/`, rejects sensor files in bundles marked without sensor data,
    and re-checks already-opened bundles.

## Fixed

- **Synthetic demo LiDAR coordinate frame (`GEN-6`) and dressed junction scene**:
  Fixed `demo-junction` so LiDAR points are written in the recording agent's
  body frame rather than world coordinates (previously the viewer applied agent
  poses a second time, shifting clouds by ~25 m and rotating `cav-b` by 90°).
  Added denser deterministic ray-cast LiDAR (681 points/sweep median, up from
  306), buildings, trees, parked cars, and richer camera renders. For seed 0,
  the full demo tree is 12.4 MiB / 13.0 MB (`scenes/demo-junction/` is 4.0 MiB),
  generation takes 11.8 s warm on Apple Silicon (24.7 s cold, 7.9 s on CI), and
  the welcome card now estimates `"about 12.4 MiB"`.
- **Non-blocking cached HPC dataset index**:
  The HPC workspace now shows the most recent scene list immediately (labelled
  cached, keyed by server, adapter, raw root, and split across restarts) while
  re-checking the raw folder in the background (`"checking for changes…"`).
  *(Note: cluster-side cause of the earlier V2V4Real `"detect 9 / index 0"`
  report remains unverified.)*
- **Multi-split navigation in the Servers sidebar**:
  The Servers sidebar now lists every recognised split of an open dataset and
  switches splits directly using detect's per-split adapter and scene count
  without running a second folder check.
- **Servers browser race condition and empty-index diagnostics**:
  Clicking a dataset now opens only the selected folder's own check once it
  completes (eliminating stale in-flight switches and stuck `"Checking what
  this folder holds…"` messages). Empty index results now surface per-scene
  errors or detect/index mismatches with a retry action, and interrupted change
  checks report inability to confirm rather than claiming changes. *(V2V4Real-shaped
  fixtures give 9 detected / 9 indexed; any real-cluster `"detect 9 / index 0"`
  root cause remains unverified and is diagnosed inline when encountered.)*
- **Security fixes**:
  Resolved remote-viewer session file injection via atomic `0600` `json.dump`
  verified by matching job ID and session ID (`SCRIPTS-01`), OpenCOOD archive
  YAML execution and PyTorch <2.6.0 weight-load exposure (`CVE-2025-32434`),
  `coperceive serve` `--root-path` auth bypass and TOCTOU/link issues on
  `jobs.sqlite`, Slurm `#SBATCH`/shell/SSH argument injection in app/CLI scripts,
  and symlink/hard-link exfiltration during `.cpbundle` export (`FOLD-03`).
