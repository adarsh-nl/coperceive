### Step B → today sbatch diff (vehicle-side, same fixture)

Old: `ba342ff` merge `fffda8a`; new: `release/v0.1.1` at `93bd5bd`. Only these
semantic differences exist (the fixture paths and repo checkout path are
normalised in the golden):

1. `#SBATCH --partition` is now the profile/CLI partition (`gpu-a40`) instead of
   the old hard-coded `ps,main-gpu`; `--slurm-partition` is required.
2. `SCRATCH` is now the profile scratch template
   (`/scratch/$USER/$SLURM_JOB_ID`) instead of `/local/$SLURM_JOB_ID`.
3. Constraint is `a40` (manifest pin) instead of `a40|a100`; the acceptance
   claim is A40-specific (`docs/models.md:158`, `:260`).
4. Time comment and estimate now include `100 s` conversion and the measured
   staging (`STAGE_START`/`STAGING`), and the inner command gains
   `--staging-seconds "$STAGING"` (`7bad3ef`). Both scripts still round to
   `01:00:00` for 1,490 samples.
5. The environment-capture heredoc (`environment.json`) is appended from #137;
   it writes package/module/CUDA provenance and is not a Slurm directive.
6. The home-copy paths are the same; the work-directory rsync filter is
   unchanged.

No change to the inner `coperceive model run` arguments other than
`--staging-seconds`; the manifest path, scenes/raw/out model and run id are
unchanged. The golden captures all of this.

## 6. Pass criteria (all cited)

- **Box count 7,930** — `docs/models.md:229`.
- **mAP** equals the `vehicle · single` row at `docs/models.md:240` for each
  config: IoU unmapped 0.5/0.7 = `0.088 / 0.074`; IoU mapped = `0.150 / 0.106`;
  centre unmapped 4/2/1/0.5 m = `0.127 / 0.117 / 0.100 / 0.081`; centre mapped =
  `0.345 / 0.296 / 0.228 / 0.148`. Values in parentheses are the model's
  internal operating point and are not the comparison target.
- **Byte-identical `boxes.parquet`** against the reference is the documented
  acceptance result (`docs/models.md:260`) **if** the job ran on an A40 with the
  pinned `a40` constraint. Exact-byte equality is the pass. If the job did not
  land on an A40, exact equality is not a pass criterion: treat the run as
  non-acceptance, and only require the same 7,930 boxes and the same mAP row;
  report the GPU and do not claim the A40 byte-identical result.

## 7. If it fails

1. **Environment/module drift** — compare `environment.json` (written by the
   job) with the reference job's: Python, torch 1.9.1+cu111, CUDA 11.8, modules,
   toolkit commit `9c02ba4a3720`, checkpoint MD5. A module change usually shows
   as a different torch/CUDA or a worker error before inference.
2. **Different GPU** — check the job card/log for the GPU type and the
   `a40` constraint. A100/L40S results can differ in scores/SASS; rerun pinning
   A40. Never present a non-A40 result as the acceptance result.
3. **Stale cache** — if the run says `cached` or the boxes look like an older
   run, rerun with `--no-cache`. The cache key changes with inputs/checkpoint;
   a stale cache is detectable from `provenance` and the run log.
